## Phase 3: Hybrid Search Engine (Week 2)

### 3.1 Smart Routing Logic
```
Query Analysis → Complexity Score → Route Decision
     ↓              ↓                    ↓
  Keywords      Heuristics           Local / Live / Both
  Length        Domain freq
  Novelty       Historical matches
```

### 3.2 Local-First for Common Queries
- Pre-computed "common query" embeddings
- Fast BM25 + vector lookup
- Verified dataset subset (high-quality records)

### 3.3 Live for Innovative Queries
- Multi-provider parallel search
- Citation graph expansion
- CrossRef, arXiv, Semantic Scholar APIs

4. Validate against schema

### 5.3 Unified Provider Interface
```python
class PaperProvider(Protocol):
```

## Technical Stack Additions

### Frontend
- **Router**: Custom hash-based + View Transitions
- **State**: localStorage + sessionStorage
- **Charts**: Chart.js (analytics)
- **Effects**: Canvas API, CSS animations

### Backend (FastAPI)
- **New endpoints**: `/api/auth`, `/api/history`, `/api/models`, `/api/providers`
- **Services**: `HybridSearchService`, `MultiModelEnhancer`, `ProviderRegistry`
- **Cache**: Redis (optional) or in-memory with TTL

### Configuration (`.env`)
```bash
# Model API keys
GEMINI_API_KEY=
OPENROUTER_API_KEY=
HUGGINGFACE_API_KEY=
GROQ_API_KEY=

# Provider toggles
ENABLE_SEMANTIC_SCHOLAR=1
ENABLE_ARXIV=1
ENABLE_CROSSREF=1
ENABLE_CORE=1

# Hybrid search
HYBRID_MODE=auto
INNOVATION_THRESHOLD=0.7
COMMON_QUERY_CACHE_TTL=3600
```
